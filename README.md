# 币安账户实时看板（Go + H5）

用 Go 写一个本地小服务：后端用你的 API Key/Secret 调用币安官方 REST 接口（HMAC-SHA256 签名），
前端是一个手机/电脑都能看的 H5 页面，每隔几秒自动刷新，实时展示账户权益、资产明细、当前委托和合约持仓。

- 现货接口：`GET /api/v3/account`、`GET /api/v3/openOrders`、`GET /api/v3/ticker/price`
- U 本位合约：`GET /fapi/v3/account`（自动兼容 v2）、`/fapi/v3/positionRisk`、`/fapi/v1/openOrders`
- 零第三方依赖，只用 Go 标准库 + `go:embed` 内嵌页面，编译出来是单个 exe

## 1. 配置

编辑 `config.json`（已内置你的 API Key，**只需补上 apiSecret**）：

```json
{
  "apiKey": "wZVu****mXrF",
  "apiSecret": "在这里填写 API Secret",
  "baseURL": "https://api.binance.com",
  "fapiBaseURL": "https://fapi.binance.com",
  "addr": "127.0.0.1:8080",
  "pollMs": 3000,
  "enableFutures": true,
  "demo": false,
  "proxy": ""
}
```

也可以用环境变量（不落盘，更安全）：

```powershell
$env:BINANCE_API_KEY    = "你的 API Key"
$env:BINANCE_API_SECRET = "你的 API Secret"
$env:HTTPS_PROXY        = "http://127.0.0.1:7890"   # 需要代理时才设置
```

优先级：命令行参数 > 环境变量 > `config.json`。

**币安侧的 Key 要求**：勾选「启用读取」（Enable Reading）即可，不要开提现、也不要开合约交易权限；
建议配置 IP 白名单。本项目只用只读接口，不会下任何单。

## 2. 运行

```powershell
cd D:\Demo
go run .                 # 直接运行
go build -o binance-viewer.exe .   # 或者编译成 exe 后运行
.\binance-viewer.exe
```

启动后打开 <http://127.0.0.1:8080/> 即可。常用参数：

```powershell
.\binance-viewer.exe -addr 127.0.0.1:8080   # 监听地址（默认只绑本机，别改成 0.0.0.0 除非你清楚风险）
.\binance-viewer.exe -pollms 5000           # 页面自动刷新间隔，毫秒（默认 5000，最小 2000）
.\binance-viewer.exe -futures-orders-sec 15 # 合约「当前委托」多久查一次（默认 15 秒，这个接口最贵）
.\binance-viewer.exe -no-futures            # 只看现货，不查合约
.\binance-viewer.exe -proxy http://127.0.0.1:7890   # 走本地代理
.\binance-viewer.exe -demo                  # 演示数据，不需要密钥，用来先看页面效果
```

## 3. 页面能看到什么

| 区域 | 内容 |
| --- | --- |
| 顶部指标卡 | 账户总权益（现货估值 + 合约账户权益）、现货估值、合约账户权益、合约未实现盈亏、可用保证金、委托/持仓数量 |
| 资产明细 | 每个币种的可用/冻结/合计、USDT 价格、USDT 估值、占总资产比例（按估值排序；稳定币按 1 计价，无 USDT 交易对的币种用 `XXXBTC × BTCUSDT` 折算） |
| 当前委托 | 现货 + 合约全部未成交挂单：交易对、方向、类型、委托价、数量、已成交、未成交、剩余价值、状态、委托时间、订单号（可按「全部/现货/合约」筛选） |
| 合约持仓 | 合约、多空方向、数量、开仓价、标记价、强平价、杠杆/保证金模式、名义价值、未实现盈亏、回报率、更新时间 |

自动刷新可随时「暂停/继续」，也可以点「立即刷新」；页面切回前台时会自动补一次刷新。

### 持仓概率（多单 / 空单）

当账户有持仓时，页面会自动多出一个「持仓概率」区块，**每个持仓一独立一块**，实时显示：

- **强平触及概率**：未来 24 小时 / 3 天 / 7 天内，价格触及你**强平价**的历史频率
- **各止盈档的摸到概率**：24 小时 / 3 天 / 7 天
- **先到止盈 vs 先被强平**：同一周期内两者的首个到达概率对比（这是真正决定期望值的数字）
- **读数提示**：自动算出「止盈距离 ÷ 强平距离」的倍数，并在先被强平占优时给出提示

**多空方向是分开算的**（关键区别）：

| | 有利方向 | 逆行方向 | 止盈档来源 |
| --- | --- | --- | --- |
| **多单** | 上涨 | 下跌（强平在下方） | `tpLevels`（只取现价**上方**的档位） |
| **空单** | 下跌 | 上涨（强平在上方） | `tpLevelsShort`（只取现价**下方**的档位） |

如果某一方向的配置档位在当前价格下都不适用，会自动退化为 **±2% / 4% / 6% / 8%** 四档（跟着现价走）。

> ⚠️ **对冲持仓的强平价**：币安在双向持仓下只给**一个标的级强平价**（由净敞口决定）。
> 如果它落在某个持仓的**同向**而不是逆行方向（例如净敞口是多头、强平价在现价下方，此时空头那一腿就没有可比的强平价），
> 页面会标注「无有效强平价」，该腿只显示"摸到各档位"的概率，**不做先后对比** —— 避免给出方向算反的假数字。

**概率档位可配置**：

```json
{
  "tpLevels":      [10.40, 9.95],          // 多单止盈档
  "tpLevelsShort": [9.31, 9.11, 8.80]      // 空单止盈档（留空则自动 ±2/4/6/8%）
}
```

命令行也可覆盖：`-tp 10.40,9.95` / `-tp-short 9.31,9.11,8.80`。

**它是怎么算的**（`odds.go`）：服务启动后第一次拿到持仓时，后台拉该币种约 4.5 万根 15m 历史 K 线
（约 1.3 年），把每一根 K 线当作一个「当前状态」，向前看 7 天，记录"先摸到上涨 u% 的最早时间"与
"先摸到下跌 d% 的最早时间"，于是对任意 (止盈距离, 强平距离) 组合都能查出历史频率。
距离按 0.5%/0.2% 网格统计，查询时线性插值。构建约需 10~40 秒（页面显示「构建中」），
之后每次刷新只是查表，开销可忽略。

> ⚠️ **模型的边界**：这是**历史频率**，不是预测。
> ① 样本是重叠窗口（连续 15m），真实置信区间比名义样本量宽；
> ② 不包含消息面、流动性突变等外生冲击；
> ③ 强平概率**没有**考虑你主动减仓/补保证金的行为；
> ④ 价格在动，概率每 5 秒会跟着变（距离变了）。
> 请把它当作"赔率尺"，而不是"预测器"。

## 4. 接口频率与限流（重要）

币安按 **IP** 限制请求权重：现货 6000/分钟，U 本位合约 **2400/分钟**，超了会先 `-1003` 限流，
继续硬打会升级成 `418 IP banned`（封禁时间会越来越长）。本程序每一轮消耗的权重大致是：

| 接口 | 权重 | 查询频率 |
| --- | --- | --- |
| `GET /api/v3/account` | 20 | 每轮 |
| `GET /api/v3/openOrders` | 6 | 每轮 |
| `GET /api/v3/ticker/price` | 4 | 每轮 |
| `GET /fapi/v3/account` | 5 | 每轮 |
| `GET /fapi/v2/positionRisk` | 5 | 每轮 |
| `GET /fapi/v1/openOrders` | **40**（不带 symbol 时） | 默认每 15 秒 |

也就是说合约侧约 `10×12 + 40×4 ≈ 280 权重/分钟`（按 5 秒刷新算），占 2400 额度的 **约 12%**，
留了足够余量。程序还做了这些保护：

- **快照缓存**：一个刷新周期最多向币安发一轮请求，多开标签页 / 狂点刷新都不会翻倍消耗；
- **自动退避**：收到 429/418/-1003 后进入冷却，冷却期间**一个请求都不发**，页面继续展示上一轮成功的数据并显示倒计时；
- **按 IP 解封时间冷却**：解析币安 `banned until <时间戳>`，封多久就等多久（最多 24 小时），不会盲目重试导致封禁升级；
- **现货/合约分开冷却**：只封了合约时，现货数据照常刷新；
- **页面右下角显示「币安已用权重 x/2400」**，可以直接看到当分钟消耗。

如果还是频繁限流：① `-pollms 10000` 再放慢；② 确认没有**重复启动多个**本程序（每个进程都会独立轮询）；
③ 如果你的机器/VPS 是共享 IP，同 IP 上别的币安轮询脚本也会一起把额度用掉；
④ 需要秒级推送就别轮询，改用币安 WebSocket 用户数据流（现货 `!userData`、合约 listenKey）。

## 5. 安全说明

- **API Secret 只存在于 Go 服务端**，浏览器访问的是本机聚合接口 `/api/snapshot`，前端拿不到任何密钥。
- 服务默认只监听 `127.0.0.1`，同一局域网/公网的其他人访问不到，也不会把账户数据暴露出去。
- ⚠️ 你在对话里公开过这组 Key/Secret，建议登录币安后**删除并重新创建一个只读 Key**，再把新的填进 `config.json`。

## 6. 常见问题

| 页面提示 | 原因与处理 |
| --- | --- |
| 尚未配置 apiKey 和 apiSecret | 填好 `config.json` 后保存并刷新页面（改配置不用重启程序，下一次刷新即生效） |
| 签名校验失败 (-1022) | `apiSecret` 填错（注意不要带空格），或用了别的 Key 的 Secret |
| API Key 无效/被禁用/IP 不在白名单 (-2015 / -2008) | 币安后台给该 Key 勾选「启用读取」，并把当前公网 IP 加入白名单 |
| 请求时间戳超出 recvWindow (-1021) | 本机系统时间不准，校准时间后重试 |
| 无法连接币安接口 | 本机网络访问不了币安（部分地区/机房被限制）。用 `-proxy http://127.0.0.1:7890` 或设 `HTTPS_PROXY` 走代理 |
| 请求过于频繁 (-1003) | 程序已自动退避；也可以把 `pollMs` 调大（5000~10000），并确认没有重复启动多个实例 |
| 当前 IP 已被币安临时封禁 (418 banned until …) | 限流升级为封禁，程序会等到解封时间再自动重试。期间现货（若未被封）仍可刷新；急用可以换 IP/代理，或改用 WebSocket |
| `go build` 报 build cache 拒绝访问 | 把 Go 缓存指到当前目录：`$env:GOCACHE="D:\Demo\.gocache"; go build -o binance-viewer.exe .` |

## 7. 文件说明

```
main.go       命令行参数 / 配置加载 / HTTP 服务 / 快照缓存
binance.go    币安 REST 客户端（HMAC-SHA256 签名、现货与合约接口封装、错误中文翻译）
snapshot.go   数据聚合（估值折算、委托与持仓整理）+ -demo 演示数据
web/index.html  H5 页面（原生 JS，无 CDN 依赖，自适应手机与桌面）
config.json   你的配置（已在 .gitignore 中，不会被提交）
```
